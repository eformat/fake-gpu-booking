= Module 3: RHOAI Hardware Profiles
:navtitle: Module 3: Hardware Profiles
:toc: macro
:toclevels: 1
:icons: font

Hardware Profiles in Red Hat OpenShift AI define the compute resources available for workbenches and model serving. In this workshop environment, they connect GPU reservations from the booking app to the RHOAI workbench experience -- when you reserve a GPU, a corresponding HardwareProfile appears so you can launch a workbench with that GPU type.

In this module, you'll explore how Hardware Profiles work, create a workbench using a reserved GPU profile, and understand how profiles link to Kueue queues.

== Learning objectives

By the end of this module, you'll be able to:

* List and inspect Hardware Profiles in your namespace
* Understand how profiles map to Kueue ClusterQueues and ResourceFlavors
* Launch an RHOAI workbench using a reserved GPU Hardware Profile
* Explain the relationship between bookings, profiles, and scheduling

== How Hardware Profiles connect to Kueue

The reservation sync creates Hardware Profiles with specific resource limits that match the Kueue queue configuration:

[cols="1,1,1,1",options="header"]
|===
| Hardware Profile | GPU Resource | CPU | Memory

| `unreserved-gpu`
| 1x `nvidia.com/gpu`
| 2
| 8Gi

| `unreserved-mig-71gb`
| 1x `nvidia.com/mig-3g.71gb`
| 2
| 8Gi

| `unreserved-mig-35gb`
| 1x `nvidia.com/mig-2g.35gb`
| 1
| 4Gi

| `unreserved-mig-18gb`
| 1x `nvidia.com/mig-1g.18gb`
| 1
| 4Gi

| `default-profile`
| none (CPU only)
| 2
| 8Gi
|===

When you make a reservation through the booking app, additional per-user profiles are created that point to your reserved ClusterQueue.

== Exercise 1: Explore default Hardware Profiles

. List all Hardware Profiles across namespaces:
+
[.copypaste]
[source,bash]
----
oc get hardwareprofiles -A
----

. Inspect the unreserved GPU profile:
+
[.copypaste]
[source,bash,subs="attributes"]
----
oc -n {user} get hardwareprofile unreserved-gpu -o yaml
----
+
Note the `spec.resources` section showing CPU, memory, and GPU limits.

. Compare with the default (CPU-only) profile:
+
[.copypaste]
[source,bash,subs="attributes"]
----
oc -n {user} get hardwareprofile default-profile -o yaml
----

=== Verify

&#10003; Multiple Hardware Profiles exist per namespace +
&#10003; GPU profiles include `nvidia.com/gpu` or MIG resource limits +
&#10003; Default profile has no GPU resource

== Exercise 2: Launch a workbench with a GPU profile

. Open the OpenShift AI dashboard.

. Navigate to **Data Science Projects** and select your project (`{user}`).

. Click **Create workbench** and configure:
* **Name:** `gpu-workbench`
* **Image Selection:** Jupyter | Minimal | CPU | Python
* **Hardware Profile:** Select one of the GPU profiles (e.g., `unreserved-gpu` or your reserved profile if you created a booking in Module 2)

. Click **Create workbench** and wait for it to start.

. Once running, verify the GPU allocation from the terminal:
+
[.copypaste]
[source,bash,subs="attributes"]
----
oc -n {user} get pod -l app=gpu-workbench -o jsonpath='{.items[0].spec.containers[0].resources}' | jq .
----
+
You should see the GPU resource in both requests and limits.

. Check which Kueue queue admitted the workload:
+
[.copypaste]
[source,bash,subs="attributes"]
----
oc -n {user} get workloads -o custom-columns=\
NAME:.metadata.name,\
QUEUE:.spec.queueName,\
ADMITTED:.status.conditions[0].status
----

=== Verify

&#10003; Workbench started with a GPU Hardware Profile +
&#10003; Pod spec shows GPU resource requests +
&#10003; Workload admitted by the correct Kueue queue

== Exercise 3: Observe profile lifecycle

Hardware Profiles created by the booking app follow the reservation lifecycle:

. When a reservation is active, the corresponding HardwareProfile exists in your namespace.

. When a reservation expires, the expiration cleaner removes the HardwareProfile as part of the two-phase drain.

. Watch for profile changes:
+
[.copypaste]
[source,bash,subs="attributes"]
----
oc -n {user} get hardwareprofiles -w
----
+
Leave this running in a terminal and observe as reservations change. Press `Ctrl+C` to stop watching.

. Clean up the workbench when done:
+
In the OpenShift AI dashboard, stop and delete the `gpu-workbench` workbench from your project.

=== Verify

&#10003; Understand that HardwareProfiles follow reservation lifecycle +
&#10003; Workbench cleaned up

== Module summary

**What you accomplished:**

* Explored the default and reservation-created Hardware Profiles
* Launched an RHOAI workbench using a GPU Hardware Profile
* Verified GPU resource allocation through Kueue queue admission
* Understood the profile lifecycle tied to booking reservations

**Key takeaways:**

* Hardware Profiles bridge RHOAI's workbench UI and Kueue's scheduling system
* Default profiles provide unreserved GPU access; reservation profiles get protected quota
* The booking app creates and removes profiles automatically as reservations change
* Users select GPU types through the familiar RHOAI workbench interface without needing to know Kueue details
